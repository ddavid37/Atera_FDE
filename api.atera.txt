Terms of Service
Atera OpenAPI v3 documentation.

Response compression
All endpoints support gzip compression. Send the Accept-Encoding: gzip request header and the response body is returned gzip-compressed; omit it to receive an uncompressed response. Prefer gzip for list endpoints and any large payload to reduce transfer size and latency.

Rate limiting
Requests are throttled per account. When you exceed your limit the API responds with 429 Too Many Requests and a Retry-After header indicating how many seconds to wait. Clients should honor Retry-After and back off before retrying (for example, retry only after the indicated delay, with exponential backoff on repeated 429s) rather than retrying immediately.

Incremental (delta) sync
Prefer delta sync over repeatedly pulling full lists. Persist the timestamp of your last successful pull and request only records changed since then using the last-modified filters, instead of paging through every record each time. For tickets, use GET /v3/tickets/lastmodified; for contacts and customers, use the FromLastModifiedDate filter. This lowers payload size, latency, and your chance of hitting the rate limit.

Accepts whole or partial emails / phone numbers. If partial, will return all contacts whose emails / phone numbers contain the input string.

Optionally filter by last modified date (format: yyyy-MM-dd) and specify sort order.

Default sort is by creation date (EndUserId descending). Set sortBy=1 to sort by last modified date.

For ongoing synchronization, prefer delta sync over repeatedly pulling the full list: pass FromLastModifiedDate (optionally with sortBy=1) to fetch only contacts changed since your last pull. This reduces payload size, latency, and your chance of hitting the rate limit.
